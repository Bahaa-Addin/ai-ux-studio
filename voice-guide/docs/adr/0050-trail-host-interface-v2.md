# ADR-0050: The trail host interface version 2: a host claims the journey at run time; the trail remembers what questions were about; a demo journey can be seeded; consent survives Vodafone's storage clear

- Status: Proposed (2026-11-13). Built in parts in phase 3 of the live plan (2026-11-14): the run-time claim on the trail's side (S8), the consent copy (S9), the layer's claim, the fallback and the `hostUrl` removal (S10); the asked questions (S14); `seed()` and `reset()` (S15); the demo kit that calls them is phase 7. Accepted when each part's checks pass
- Date: 2026-11-13
- Area: Exploration Trail (SPEC-06), journey host, privacy; amends ADR-0037 §1 (where consent is kept), ADR-0040 §1–2 (how a page hosts the journey), ADR-0046 §4 (the journey hosted in the Pocket on every page); supersedes ADR-0043 §2 (the host page chosen by language through `trail.hostUrl`); delivers ADR-0048 §2 (the host is claimed at run time, never declared by the loader)
- Owner decisions: 2026-11-10, one interface change, version 2, covering the run-time claim, what questions were about (the RED world revamp, `docs/wiki/Demo 5 revamp - personalization for an anonymous visitor.txt` Part A) and a consent-gated `seed()` for the demo kit; ADRs numbered in the order they are written, so this one takes 0050. 2026-11-13, where no page can host the journey it opens in the guide's own sheet

## Context

Version 1 (`packages/sdk/src/trail/host.ts`) lets a page that draws the journey in its own design drive the trail: the page declares itself with `<meta name="vg-trail-host" content="pocket">`, listens for `vg:trail-ready` (detail: the API, also published as `voiceGuide.trailHost`) and `vg:trail-open` (the person pressed "Your journey"), and calls `open`, `select`, `scrub`, `ask`, `allow` and the rest. Only the Services clone's HTML carries that meta. Measured or read on 2026-11-13 (`docs/reference/live-way2-phase3-map-2026-11-13.md`, "journey-host"):

- The trail decides once, in a read-only field, whether the page hosts the journey (`readonly hosted = !!document.querySelector(…)`, `controller.ts:136`). ADR-0048 §2 rejected a meta added by the loader: the layer can be off, fail or have no Pocket, and the pill would then send `vg:trail-open` to nobody, with no way for the layer's guard to undo it.
- On other pages the pill navigates to `trail.hostUrl` (`/{lang}/services#journey`, ADR-0043). On Vodafone's live pages nothing hosts the journey there, so the pill opens nothing. And because the pill treats a set `hostUrl` as "hosted" (`controller.ts:510`, `view.ts:497`), the guide's own sheet never shows.
- The clone's `journey.js` refuses any host whose `version` is not 1 (`journey.js:503`).
- The trail stores no question. The revamp needs what questions were about (never their words), per step.
- The demo kit (live plan §3.6) needs to load a sample journey after the person consents.
- Consent is a `localStorage` key (`vg-trail:<siteKey>:consent`, `consent.ts`). Vodafone's signed-out theme clears `localStorage` on every load of home, Services, RED and Vodafone Cash (O23), so consent is lost on the next page (T-806). The trail's own journey data is in IndexedDB (`vg-trail-v1`), which the theme does not touch.
- Any script on the page can call `voiceGuide.trailHost.allow()` and grant consent without a press (`controller.ts:569`).
- Room: `guide.js` 20,315 B gzipped of 20,480; `trail.js` 27,135 of 30,720 (`tests/unit/sdk-size.test.ts`, measured 2026-11-13).

## Decision

1. **One version, 2, a superset of version 1, all in `trail.js`.** `guide.js` gains nothing. `host.ts` carries a changelog. A host reads version 2 fields only when they are present; `journey.js` accepts `version >= 1`, and the version change and that `journey.js` change land in one commit.
2. **A host claims the journey at run time.** `claim()` returns a `release()` function, or `null` when another host holds it: one host at a time. Readers that only show journey facts (the RED world) subscribe and never claim. `hosted` becomes a live value that every reader uses. A claim made while the guide's sheet is open hands over (the sheet collapses, then `vg:trail-open`). A release collapses the journey, destroys its preview, empties the host's preview root and re-renders, so the pill works again at once. The clone's static meta counts as a claim that is never released, until phase 9 removes the clone. The experience layer claims on `vg:trail-ready` when its Pocket can host, and registers the release with its guard, so a failure of the layer gives the journey back.
3. **Where "Your journey" opens.** With a host, in the host (`vg:trail-open`). Without one (the `/spa/` app, the shop, `?aixc=off`, the layer off or failed), in the guide's own sheet (ADR-0038). `trail.hostUrl`, its `{lang}` code and the session flag that reopened the journey after the trip are removed. The pill never navigates.
4. **The step the journey opens on.** When a live page hosts, the current page (it is a real step of the visit). The clone keeps the step before the Services page, which is not a step of interest there, until phase 9.
5. **What questions were about (phase 5).** The trail wraps the guide's `request` in `trail.js` and records, from the plan's `meta` of each answered turn, one asked question on the current step: `{ id, at, lang, origin, destinationId, pageId, intent, route, label }`, at most 10 per step. Only while recording and on a page step; nothing when no destination was resolved; never the words said or typed, never the answer (live answers carry prices). The server adds `meta.pageId` and a price-free `meta.label` to the plan. `snapshot().asked` (newest first), `askAbout(destinationId, questionId?)` (resolved across every step and the page map) and `questionsFor(destinationId)` expose them. The consent copy says so: the trail keeps the pages visited, what was explored there and what the questions were about, never the words.
6. **A seeded journey (phase 7).** `seed(journey)` replaces the current journey with a sample one, only when all three hold: consent is granted, the call follows a press (`navigator.userActivation.isActive`), and the server's session says the page is a demo (`experiences.demos.demoKit`). The journey is validated with the trail's own parsers and limits, gets new session and step ids, and has its times moved to end now, within the 30-minute session limit. `reset()` clears the journey and returns consent to unset, for "Reset demo".
7. **Consent needs a press.** `allow()` from a host is honoured only after a press on the page. Any script can still read `voiceGuide.trailHost`; that is accepted for the owner's demos and recorded for the customer decision (PRD D2).
8. **Consent survives the theme's clear.** The consent record is also kept in the trail's IndexedDB. At start the trail reads `localStorage` and, when the key is missing, the IndexedDB copy, and puts the key back. A clear seen from another tab (a `storage` event with no key) is not a change of consent. Tabs tell each other about consent through a `BroadcastChannel`. "Turn off" writes `off` to both copies (ADR-0037 §1: the offer stays hidden until the person turns it on again); "Clear" and "Clear all" remove the journey and leave consent as it is; only `reset()` (decision 6) removes both copies. (Corrected 2026-11-13, AIXC-62: this sentence first said "Turn off" and "Clear" remove both copies, which would have ended consent silently on "Clear" and brought the offer back.) `Storage.prototype` is never patched; the demo browser's `vg-` guard stays for replay only. Amends ADR-0037 §1.
9. **`ask()` finds the language** the same way the host does: the guide's language, then its first two letters.

## Consequences

- "Your journey" works on every page the layer runs on, opens in place, and falls back to the guide's sheet everywhere else; no pill is ever dead.
- A failure of the experience layer releases the journey; the next press opens the sheet.
- `trail.js` grows by the claim, the IndexedDB consent copy and, later, the asked questions and `seed()`: each part is measured against the 3,585 bytes left, and the budget is raised only on purpose.
- The clone and its tests keep working until phase 9, through the meta.
- With `seed()` a demo can start with a journey, but only after a person consents and presses; a page script cannot seed one.
- The trail keeps one more kind of thing (what questions were about). The consent copy and its e2e check change with it.

## Built (S8, 2026-11-14): the trail's side of the claim

- `host.ts` is version 2 with a changelog; `claim()` returns `release` or null. `controller.ts`: `hosted` is a getter (the clone's meta, which is for good, or a claim); every reader used it already, so each follows a claim and a release. A claim made while the sheet is open collapses it and then, on the next tick and only if the claim still stands, dispatches `vg:trail-open`. `release` works once and only for the current claim: the journey collapses (which destroys the preview), the host's preview root is emptied, the pill works again at once. `ask()` finds a question under the language or its first two letters. The journey opens on the page the person is on when a host claimed; the clone's meta keeps the step before the Services page.
- `journey.js` accepts any version from 1 (a host with no version, or a fake one, is still ignored), in the same commit.
- **Where the layer claims moves from the core to the Pocket chunk, and to step S10.** The core has 79 B left of its budget, and a claim whose journey is not drawn yet would be a dead pill (the ADR's own rule: no pill is ever dead). So no layer claims in S8; step S10 draws the journey in the live Pocket and its chunk claims on `vg:trail-ready` (or at once when `voiceGuide.trailHost` exists), registers `release` with the guard, and the plan's check "a forced layer failure after the claim, then a pill press, opens the fallback" is run there.
- Everything in the decisions is built (S8 to S15). What remains are the consumers: the RED world (phase 5, `asked`, `askAbout`, `questionsFor`) and the demo kit (phase 7, `seed()`, `reset()`).
- Checked: `tests/integration/trail-host.test.ts` (Chromium, the real controller with a stand-in guide, 6 tests, all failing on the version 1 code): the pill asks the host and never opens the sheet while claimed, a second claim is refused, giving it back brings the sheet back at once, a claim over an open sheet hands over, a release while the host has the journey open closes it and empties its preview root, a stale release does nothing, the meta host is for good, `ask()` in `en-GB`. `trail.js` grew by 106 B gzipped (28,249 to 28,355 of 30,720, 2,365 B left); `guide.js` is byte-identical (same hash with and without the change).

## Built (S9, 2026-11-14): consent survives the theme's clear (decision 8)

- `consent.ts`: every `writeConsent` also writes the choice to **a small IndexedDB database of its own, `vg-trail-consent`** (one object store, keyed by site key), in the order the choices were made so the last one is kept. At start, `recoverConsent` reads `localStorage` and, when the key is missing, the copy, and puts the key back as it was written. A read never creates the database (a database that does not exist yet is cancelled as it is made), so a visitor who chose nothing has nothing stored. **Two refinements of decision 8:** the copy is not inside the journey's database (`vg-trail-v1`), which turning the trail off deletes: "off" is a choice that has to be remembered, and a second object store would have needed a version upgrade of that database; and no `BroadcastChannel` was built, because tabs already hear each other through the `storage` event, and what the other tab wrote is now taken from the event (`newValue`), not from storage as it stands a moment later, so a clear that follows cannot undo it. A clear (a `storage` event with no key) or a removal reads as no change.
- Checked: `tests/integration/trail-consent.test.ts` (Chromium, 5 tests: a read creates nothing; the choice and the key come back after a clear for granted, paused and off; the last of six quick choices is kept; a trail started after the clear has the choice and "off" stays off; a tab follows what another wrote and ignores a clear; with the copy's fallback removed three of them fail, and with the handler re-reading storage the fifth fails) and `tests/e2e/trail-consent.e2e.test.ts` (port 4488, on the saved pages with the theme's clear stood in: allowed once on home, the trail still consents and records across Services, bundles, Vodafone Cash and home, then the Arabic pages; turned off, it stays off after the pages that clear; both fail on the code before S9); `trail.e2e` 8/8 (including pause, resume and revocation across tabs). `trail.js` +319 B gzipped (28,355 to 28,674 of 30,720).
- Not verified: the real theme's clear (O29); Safari's treatment of an IndexedDB database nobody has opened for a week (its storage rules for sites the visitor does not use may drop it, and then consent is asked again, the safe direction).

## Built (S10, 2026-11-14): the journey in the live Pocket; `hostUrl` gone

- **The layer's side.** `host/demos/pocket.js` hosts the journey where the trail offers a host it can claim (version 2 with `claim()`, found in `voiceGuide.trailHost` at start or on `vg:trail-ready`; a fake or version 1 host is ignored). The journey is `host/demos/journey.js`, a chunk of its own that the Pocket chunk loads, so no page without a trail pays for it (8,226 B gzipped, budget 8.75 KB; the Pocket chunk 31,715 B of 32,000). `journey.js` takes the host's seams: the header, `mark` (data-aixc and data-vg on the nodes it adds), `wrap` and `listen` (every handler, the window listeners and the trail's render through the guard, which the trail's own catch would otherwise hide), `claim`, `checkpoint` and `bandTop`; the defaults are the clone's, which is unchanged. It claims through `api.claim()` and draws nothing if another host holds the journey; the release is registered with the guard before the journey exists and `destroy()` gives the claim back, unsubscribes, empties the preview root and removes its nodes, so a stop (a failure, `?aixc=off` at run time) leaves the pill working. Test hooks: the checkpoints `journey-claim` and `journey-open`. One element helper is copied from `pocket.js` on purpose: sharing it split the Pocket's chunk in two (+750 B gzipped, over its budget).
- **The trail's side.** `trail.hostUrl` is gone: the setting, its schema, what the gateway sends and the yaml entry (an old yaml that still has it loads: unknown keys are dropped); so are the sessionStorage open flag and the pill's navigation. A consented press asks the host while one holds the journey and otherwise toggles the guide's own sheet, so the pill is never dead and never leaves the page (OD-5, owner 2026-11-13: the sheet returns on the `/spa/` app, the e-shop, `?aixc=off` and a failed layer). This completes decision 3, and supersedes ADR-0043 §2.
- **The band is fixed by script on live pages.** `position: sticky` does not hold on Vodafone's themes: `html` and `body` compute `overflow-x: hidden` on home, Services, bundles and Cash (measured on the saved pages; the band was gone after a 568 px scroll). The band sits in a slot that keeps its place and is held fixed below `host.chromeBottom()` (Vodafone's pinned navigation is 68 px while `#header` shrinks to 27), carried up by the album's end; it reads nothing while the album is hidden. Vodafone's `html` and `body` are never touched. The clone keeps `sticky`. The journey's fonts are the album's variables, so Arabic live pages get Vodafone's `-ar` families.
- **Checked** (a scratch worktree on 7e07d3c with only S10's changes; the work was built by teammates and every diff and result read and re-run by the lead): typecheck ok; `npm test` 293/293; `test:e2e` 108/108; experiences `npm test` 191/191; the clone's suites aixc 298, arabic 71, pocket 210, tips 87, portal 54 of 56 (AIXC-95). New: `tests/e2e/pocket-journey-live.e2e.test.ts` (port 4489, 9 tests on the saved pages, all failing on 7e07d3c: the journey opens in place on `/en/vodafone-cash`, `/en/mobile-internet-bundles` and `/en/wireless-net` (no cards) with the URL unchanged, no navigation, no sheet and the current page selected; Arabic right to left; closing returns to the same scroll within 2 px with Vodafone's frame as served; `?aixc=off` and `/spa/storeLocator` open the guide's own sheet; a failure at `journey-open` or `journey-claim` removes the layer and the next press opens the sheet; a question chip sends the trail's hint with the chip's destination; no replay data in any request and every journey node marked), three new tests in `tests/integration/trail-host.test.ts` (the pill never navigates, with a stale `hostUrl` or the old flag), `experiences/tests/pocket-journey.test.mjs`, and the budgets in `tests/unit/sdk-size.test.ts`. The two clone tests that went through `hostUrl` were removed; the clone's other four stay.
- **Not verified.** The live pages (O29); phone widths and long albums for the held band, and the band during the page turn; the e-shop; a real screen reader. **Known gap (AIXC-119):** opening the journey from the pill does not move focus into it, so one Escape closes the journey and the album together (as on the clone). **Not a bug of this step:** where the journey shows a note without a question chip (English Cash), the profile's English question is `needs-review` (router confidence 0.38) and only verified questions are shown (207 of 494 English, 171 of 548 Arabic).

## Built (S14, 2026-11-15): what questions were about (decision 5)

- **Recording** (`packages/sdk/src/trail/asked.ts`, `watchTurns`): the trail wraps two members of the guide object, not `guide.ts`: `request` (to learn how the question was asked: `voice`, `typed` or `chip`) and `api.post` (the `/v1/turn` reply is the only place the plan can be read: `guide.request` returns nothing). From the reply it reads `plan.meta` and `plan.lang` and nothing else; it never reads the request body, `plan.say` or `plan.steps`, and keeps no argument beyond the call. The wrap is undone on `destroy()`. One asked question `{ id, at, lang, origin, destinationId, pageId?, intent, route, label? }` goes on the current step, only while `rec === 'recording'`, on a page step, when the meta has a `destinationId`, and for an answered turn (a failed post records nothing); at most 10 per step (`TRAIL_CONFIG.storage.maxAskedPerStep`), the oldest dropped; written to the index at once and into the `sessionStorage` stash on `pagehide`, like explored items. `intent` is the router's fixed intent id or `flow:<flowId>`, not text.
- **Server** (`packages/kb/src/plan.ts`, `services/router/planner.ts`): the plan's `meta` gains optional `pageId` and `label` (old plans and the clone's still validate). `label` is the destination's first label in the turn's language, passed through `priceFreeLabel()`: it is **left out, not cleaned**, when it has `%` or `٪`, a number next to a currency word in English or Arabic (EGP, L.E, £, جنيه, ج.م, قرش ...), or anything the router's value filter would remove; at most 60 characters. Bare numbers in names ("Flex 1400", "5 GB") are kept. The trail checks the label again on its side (a label from an older server with a price is dropped).
- **Storage** (`types.ts`, `parseSession`): `TrailStepSummary.asked?` is kept only for valid entries, known fields, at most 10; sessions without it still parse; `isChunk` and `decodeChunk` are unchanged (replay chunks never hold asked questions; there is no export; the contribution batch uses attention records only). "Clear", "Clear all", "Turn off" and expiry remove them with the session.
- **Host interface** (`host.ts`, still version 2, a changelog entry): `snapshot().asked` (newest first, across steps, each with its `stepId`; present while consent is granted or paused and a journey exists; `snapshot().steps` keep the version 1 shape), `askAbout(destinationId, questionId?)` (the asked questions about that destination from every step; with a `questionId` it also asks that verified question like `ask()`, the destination being found across every step's explored items, then the page map's destinations and pages), `questionsFor(destinationId)` (the verified questions in the guide's language or its first two letters; empty when none).
- **Consent copy** (`trail/i18n.ts`, both languages): "What is saved: the public pages you visited (how they looked, where the pointer moved and scrolled), what you explored there, and what your questions were about, never the words you said or typed." and "Never saved: the words you say or type, the guide's answers, form fields, sign-in, your account, payment, or private pages." The Arabic (Egyptian register, like the rest) needs a native reviewer. `trail.e2e.test.ts` asserts the new wording.
- **Tests:** `tests/unit/trail-asked.test.ts` (6), `tests/unit/plan-meta.test.ts` (3), `tests/integration/trail-asked.test.ts` (Chromium, the real controller with a stand-in guide: a distinctive utterance, a phone-like number in it, the answer and "46 EGP" are absent from every IndexedDB database and store, `localStorage`, `sessionStorage` and the snapshot; a question asked on step 2 shows in `askAbout` from another step; "Clear" empties it); all failed before the change. Checked by the lead in a separate worktree: typecheck ok; `npm test` 304/304 (293 + 11); `sdk-size` 4/4 (`trail.js` 29,743 B gzipped of 30,720, was 28,605: +1,138 B, budget not raised); `trail.e2e` 8/8, `trail-consent.e2e` 2/2, `pocket-journey.e2e` 4/4, `pocket-journey-live.e2e` 9/9.
- Not built or not verified: no consumer yet (the RED world, phase 5); a real server turn end to end through the real `guide.ts` (only the stand-in guide that posts `/v1/turn` as `guide.ts` does); `origin` is only what the guide exposes (`chip` covers the guide's chips, the trail's chips and `askAbout` alike); a priced title is omitted, not replaced by its parent's title.
## Built (S15, 2026-11-15): `seed()` and `reset()` for the demo kit (decision 6)

- **`seed(journey)`** (`packages/sdk/src/trail/seed.ts`, `controller.ts`, `host.ts`) returns a promise of `{ ok: true }` or `{ ok: false, reason }` and never throws to the page. Four gates are checked in the same tick as the call, before anything is awaited: the session's `trail.demoKit` is true (new: `services/gateway/server.ts` `trailSettings` sends `site.experiences.demos.demoKit`), consent is `granted`, `navigator.userActivation?.isActive` is true (refused where it is missing), and the trail's whole eligibility check passes (an opted-out page, a private page, a sensitive path or private fields refuse with `not-here`). Reason codes: `not-a-demo`, `no-consent`, `no-press`, `not-here`, `busy`, `invalid`, `version`, `too-big`, `too-long`, `failed`.
- **Validation** (`checkSeed`): the input is `structuredClone`d first (no getters, functions or proxies; the input is never changed), walked as plain data only (short strings of at most 500 characters, finite numbers, lists of at most 50, no `__proto__`, `constructor` or `prototype` key), checked against an exact key whitelist for the seed, session, step, navigation cause, explored item, question and asked question, then by `parseSession` (which must keep every step), the trail's own limits (at most 20 steps, 10 asked questions per step, a span under 30 minutes), every `canonicalPath` on this page's origin, steps in order with unique ids, and each replay through `isChunk` and `decodeChunk` (an event the decoder would drop refuses the whole journey; events in order; a span under 30 minutes; at most 256 KB per replay and 20 MB in all). Anything wrong refuses the whole journey; nothing is partly seeded. An explored item's `kind` (it names an icon) must match `^[a-z][a-z0-9-]{0,39}$` and not be a property every object has. The views render titles with `textContent` (a test puts markup in titles).
- **What is stored:** a copy with new session, step and asked-question ids (a hostile input id never overwrites a real one), times moved so the journey ends now, `siteId` and `kbVersionId` from this page, an expiry of now plus the retention, one chunk per step as the recorder stores them; the old current journey is deleted; other tabs adopt it through the trail's own `seeded` key. Consent is never changed and the recorder is not started or stopped: the page the person is on always becomes a new step after the sample (a forced new step), so live events never mix into a seeded step. **The input** is `SeedJourney = { v: 1, session: <a TrailSession as stored>, chunks?: { [stepId]: string } }`, each string the JSON text of that step's events (a `json` chunk's data, or a `gzip` chunk decompressed, joined in order); a step without a replay is allowed and has no preview.
- **`reset()`** (only when `demoKit`; it needs no press: deleting data is the safe direction): drops buffered events, clears the session and its stashes, forgets "Not now", stops the recorder and the replayer, sets consent to **unset** (the offer shows again), removes both consent copies (`localStorage` and the IndexedDB record, S9) and empties every journey through the existing clear-all path; other tabs reset only when the consent key is really gone, so a forged `reset` key does nothing. It touches no key of Vodafone's.
- **Tests:** `tests/unit/trail-seed.test.ts` (6) and `tests/integration/trail-seed.test.ts` (8, Chromium, the real controller): a refusal per gate (reason, nothing stored, the current journey untouched), malformed, oversize and prototype-shaped inputs, ids regenerated, times rebased, survives the next index write and a reload, shown to subscribers, "Clear" removes it, markup rendered as text, consent unchanged, `reset()` in both consent copies, refusal without `demoKit`; all failed before. Checked by the lead in a separate worktree on `e96da8a` plus S15: typecheck ok; `npm test` 353/353; `sdk-size` 4/4 (**`trail.js` 32,061 B gzipped, +2,318 B, so its budget is raised on purpose to 31.5 KB (32,256 B)**; `seed.ts` alone is about 2.1 KB, mostly its key lists); `trail.e2e` 8/8 (twice; see the harness note), `trail-consent.e2e` 2/2, `pocket-journey.e2e` 4/4, `pocket-journey-live.e2e` 9/9.
- **What a page script can still do** (accepted for the owner's demos, PRD D2): the press gate is transient activation, so any script within about 5 s of any press by the person can seed once consent is granted and `demoKit` is on (Playwright's `page.evaluate` also grants activation); any same-origin script can write the trail's IndexedDB and keys directly, as before S15 (what is read back goes through the lenient `parseSession`); any script can call `reset()` with no press when `demoKit` is on (it deletes the trail's data and shows the offer again). A seeded replay brings in a DOM snapshot that was never recorded in this browser: it is shown only through the existing replay path (sanitised events, a sandboxed frame with no scripts, a policy, same-origin static resources).
- **Not verified:** the real demo kit (phase 7) exporting and seeding a real journey (a full snapshot of a Vodafone page may exceed 256 KB; the kit may need short steps); the seeded replay actually playing in the preview; `seed()` through the real `guide.ts` and gateway end to end; Safari and Firefox (`navigator.userActivation`).
- **A follow-up the lead plans:** `trail.js` carries `seed.ts` for every visitor although only the demo kit calls `seed()`; moving the validation into an on-demand chunk loaded after the gates would take 2.1 KB off every visitor's trail load and return the budget to 30,720 B.
